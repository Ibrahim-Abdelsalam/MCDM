\section{Executive Summary}

The Draft.tex document describes a nine-stage, bi-directional decision-support architecture integrating Multi-Criteria Decision Making (MCDM), Machine Learning (ML), Reinforcement Learning (RL), and Blockchain technologies. 

While the current codebase implements the core mathematical MCDM algorithms correctly, recent analysis has identified several \textbf{foundational architectural gaps} that must be resolved to elevate the system from a prototype to a professional, research-grade tool. These include rigid hardcoded criteria, a lack of causal dependency analysis (DEMATEL), reliance on single-expert input rather than Group Decision Making (GDM), and an over-reliance on synthetic data.

Table~\ref{tab:executive-summary} provides an at-a-glance summary of the nine stages defined in the Draft and their implementation status.

\subsection{Key Findings \& Newly Identified Gaps}

\begin{itemize}
    \item \textbf{Strengths:} The MCDM ranking core (Stage IV) is mathematically robust, implementing AHP, TOPSIS, and VIKOR (including compromise conditions) flawlessly. The bi-directional evaluation framework is fully operational.
    \item \textbf{Gap 1 (Rigid Criteria):} Criteria are currently hardcoded. The system requires a dynamic CRUD (Create, Read, Update, Delete) interface to be practically useful in real-world procurement.
    \item \textbf{Gap 2 (Validation \& Data Reliability):} The system relies on synthetic random data. A robust CSV/Excel importer is required. Furthermore, \textbf{Sensitivity Analysis} is missing, which is critical for verifying the robustness of the MCDM rankings.
    \item \textbf{Gap 3 (DEMATEL \& GDM):} The weighting stage (Stage III) lacks DEMATEL integration to handle criteria interdependencies. It also lacks Group Decision Making (GDM) to aggregate multiple experts' matrices.
    \item \textbf{Gap 4 (Time-Series Data):} The current data structure captures only a single snapshot in time. To enable Machine Learning (Stage V), the data model must be refactored to support longitudinal (period-by-period) evaluation tracking.
\end{itemize}

\section{Detailed Stage-by-Stage Comparison}

This section examines each of the nine stages defined in the Draft and compares what was planned against what currently exists, highlighting the newly discovered foundational gaps.

% --------------------------------------------------
% STAGE I
% --------------------------------------------------
\subsection{Stage I: Data Acquisition and Preprocessing}
\label{sec:stage1}

\subsubsection{What the Code Implements}
\begin{itemize}
    \item \done\ \textbf{Company Profile Management:} JSON-based persistence of supplier/buyer scores.
    \item \done\ \textbf{Synthetic Data Generation:} Generates 10 to 10,000 entities for stress-testing.
    \item \done\ \textbf{Normalization:} Both Vector and Min-Max normalization are implemented.
\end{itemize}

\subsubsection{What is Missing (Critical Foundational Gaps)}
\begin{itemize}
    \item \partial\ \textbf{Real-Data Import Mapping:} The system cannot currently ingest real-world data from Excel or CSV files. A mapping interface is required to map spreadsheet columns to the system's dynamic criteria.
    \item \partial\ \textbf{Time-Series Data Structuring:} Currently, the system only stores a single score snapshot per company. To predict future performance (Stage V), the system must store data in periods (e.g., Q1 2025, Q2 2025).
\end{itemize}

% --------------------------------------------------
% STAGE II
% --------------------------------------------------
\subsection{Stage II: Screening via Binary Qualification Gates}
\label{sec:stage2}
\notdone\ \textbf{No screening logic exists in the codebase.} 
The system requires a module to process binary (pass/fail) criteria (e.g., ISO certifications, capacity limits) to filter unqualified entities before executing the expensive MCDM algorithms.

% --------------------------------------------------
% STAGE III
% --------------------------------------------------
\subsection{Stage III: Criteria Weighting using MCDM Methods}
\label{sec:stage3}

\subsubsection{What the Code Implements}
\begin{itemize}
    \item \done\ \textbf{Direct Weighting:} Standard normalized direct assignment.
    \item \done\ \textbf{AHP \& FAHP:} Complete pairwise matrices, consistency checking (CR $\leq 0.10$), and Buckley's fuzzy geometric mean with Center-of-Area defuzzification.
\end{itemize}

\subsubsection{What is Missing (Critical Foundational Gaps)}
\begin{itemize}
    \item \partial\ \textbf{DEMATEL Integration:} AHP assumes all criteria are independent. DEMATEL (mentioned in the Draft's literature review) is required to map the causal relationships between criteria and adjust the AHP weights accordingly (DANP).
    \item \partial\ \textbf{Group Decision Making (GDM):} The current system assumes a single expert provides the pairwise matrix. Professional systems aggregate judgments from multiple experts (e.g., via the Geometric Mean of their matrices).
\end{itemize}

% --------------------------------------------------
% STAGE IV
% --------------------------------------------------
\subsection{Stage IV: Alternative Ranking}
\label{sec:stage4}

\subsubsection{What the Code Implements}
\begin{itemize}
    \item \done\ \textbf{TOPSIS:} Full implementation (PIS/NIS, Euclidean distances, closeness coefficient).
    \item \done\ \textbf{VIKOR:} Full implementation (Utility $S$, Regret $R$, Compromise Index $Q$, and both stability conditions).
    \item \done\ \textbf{Multi-Method Orchestrator:} Runs all solvers in parallel.
\end{itemize}

\subsubsection{What is Missing}
\begin{itemize}
    \item \partial\ \textbf{Sensitivity Analysis:} A crucial validation feature is missing. The system must allow users to slightly adjust the weight of one criterion to visualize how robust the final supplier rankings are under varied priorities.
\end{itemize}

% --------------------------------------------------
% STAGES V through VIII
% --------------------------------------------------
\subsection{Stages V -- VIII: Advanced Integrations}
\notdone\ \textbf{Not Started.} 
As established in previous analyses, the Machine Learning (Stage V), Hybrid Scoring (Stage VI), RL Matching (Stage VII), and Blockchain (Stage VIII) layers have not yet been built. They are dependent on the foundational fixes outlined in Stages I-IV being completed first.

% --------------------------------------------------
% STAGE IX
% --------------------------------------------------
\subsection{Stage IX: Output, Monitoring, and Feedback Loop}
\label{sec:stage9}
\begin{itemize}
    \item \done\ \textbf{Reporting:} Excel exports and Chart generation (bar/scatter) are fully implemented.
    \item \notdone\ \textbf{Scenario Planning (What-If):} The system lacks the ability to test hypothetical scenarios (e.g., "What if Supplier C's capacity drops by 30\%?").
\end{itemize}

\section{Criteria Definition \& The Rigidity Flaw}

\subsection{The Hardcoded Criteria Problem}
Currently, the system hardcodes 8 supplier criteria and 9 buyer criteria in \texttt{app/core/criteria.py}. 

This represents a major architectural limitation. A professional decision-support system cannot have hardcoded criteria. To be practical for real-world validation, the system requires a \textbf{Dynamic Criteria Manager (CRUD)}. 
\begin{itemize}
    \item Users must be able to Add, Edit (Name, Benefit/Cost type), and Delete criteria directly from the GUI.
    \item The entire application (pairwise matrices, datasets, reports) must dynamically generate based on this user-defined configuration.
\end{itemize}

\section{Prioritized Development Roadmap (Revised)}

Based on the identification of these foundational gaps, the development roadmap has been restructured. The focus is now on ensuring the system's core is dynamic, realistic, and defensible before adding advanced AI or blockchain layers.

\subsection{Phase 1: Dynamic Foundations (Estimated: 1--2 weeks)}
\begin{enumerate}
    \item \textbf{Dynamic Criteria (CRUD):} Refactor the architecture to support user-defined criteria.
    \item \textbf{Real Data Importer:} Build a CSV/Excel import tool with column mapping.
    \item \textbf{Time-Series Structuring:} Update the data models to support evaluation "Periods" to prepare for Machine Learning.
\end{enumerate}

\subsection{Phase 2: Advanced MCDM \& Validation (Estimated: 2--3 weeks)}
\begin{enumerate}
    \item \textbf{DEMATEL Integration:} Add causal relationship analysis and DANP weighting.
    \item \textbf{Group Decision Making (GDM):} Add support for multiple expert matrices and aggregation.
    \item \textbf{Sensitivity Analysis:} Build interactive dashboards to test ranking robustness.
\end{enumerate}

\subsection{Phase 3: Qualification Screening (Estimated: 1 week)}
Implement Stage II: Binary pass/fail gates to filter unqualified entities.

\subsection{Phase 4: Machine Learning (Estimated: 4--6 weeks)}
Implement Stages V and VI: Predictive modeling using the time-series data established in Phase 1, and hybrid score fusion.

\subsection{Phase 5: Intelligent Matching (Estimated: 4--6 weeks)}
Implement Stage VII: Gale-Shapley matching and the Reinforcement Learning (RL) agent.

\subsection{Phase 6: Trust \& Feedback (Estimated: 6--8 weeks)}
Implement Stages VIII and IX: Hyperledger Fabric smart contracts and continuous feedback loops.
